Every /admin page, in the refreshed system

The Labs experiment gave the admin a quieter surface: charcoal field, hairline lists, labeled rail, pill controls. This pass goes page by page and applies the same handful of parts to every route, removing the duplicated chrome, the second way to do the same thing, and the per-page save models along the way.

Step two

Eight rules, then the pages follow

The Labs theme changed tokens. These rules change structure. Each one removes a class of inconsistency the route audit turned up.

  • 1 · One shell, three widthsRail 224px with labels. Secondary pane 236px. Content. Feedback, Support, Roadmap, Changelog, Help Center, Status, Analytics, Users, AI & Automation and Settings all use the same pane component. Today four hand-rolled copies exist.
  • 2 · Pane grammar is fixed13px/600 section heading, optional + action, rows with a right-aligned count. Active row: neutral fill, gold count. Cross-links (public page, page settings) go under an “Other” section at the bottom, never as inline paragraphs.
  • 3 · Records open in a sheetPost, roadmap card, changelog entry, article, incident and person all open in a right-hand sheet over their list, with a crumb, state pill and actions in the sheet head. Conversations and tickets keep a persistent thread pane. No more dialog-versus-sheet-versus-in-place split.
  • 4 · Sub-views are a tab stripLine tabs with a short gold underline. Used for settings modules (Boards · Statuses · Tags · Moderation), agent pages, security, developers, billing, and inside sheets. Status’s six ?view= modes become pane rows instead, because they are navigation, not views of one thing.
  • 5 · Three save models, chosen by contentSwitches, selects and radios save instantly, with a “Saved” whisper. Text and forms share one sticky save bar per page (Discard · Save changes). Records created or edited in a dialog or sheet keep their own footer. No per-card Save buttons anywhere.
  • 6 · One managed listStatuses, tags, labels, ticket types and statuses, macros, SLA policies, skills, guidance, connectors, API keys, webhooks, attributes, domains, teams, roles, services: the same row (grip · swatch or icon · name and pills · sub-line · trailing status · hover actions) with an add row at the end. Drag to reorder everywhere it applies; up/down buttons go.
  • 7 · Primary action lives in the headOne gold button per page, in the page head. Create menus, empty states and add rows may repeat it, cards may not. Report incident, New post, Invite, New workflow.
  • 8 · Hubs and orphans get a homeSettings module hubs and thin menu pages are replaced by the first tab. Moderation joins the Feedback pane as “Pending review”. Overview becomes Home with a rail row. Notifications uses the standard page head.

Kept from the Labs pass: gold only as an accent (ticks, counts, focus, underlines, the one primary button), hairlines instead of shadows, 8px fields, 12px panels, pill buttons and search, light sibling with the same geometry. Workspace branding still overrides everything.

Step three

A sequence that ships behind the same Labs switch

  • 1 · PrimitivesPane, page head, tab strip (the unused tab-strip.tsx), managed list row, save bar, sheet shell. All refined-gated. No page changes yet.
  • 2 · Settings modules on tabsHubs redirect to first tab; nav collapses to five modules. Boards, Statuses, Tags, Moderation first, then Support. Highest visible simplification for the least logic change.
  • 3 · Lists onto the shared paneRoadmap, Support nav, Analytics adopt the pane component. Status views become pane rows. Moderation joins Feedback.
  • 4 · SheetsPost sheet replaces PostModal and RoadmapModal. Changelog and article sheets adopt the same head. Users detail becomes a sheet.
  • 5 · Save barsPortal already has the draft model; extend it to Messenger, Help Center, board detail, roles, general. Remove per-card Save buttons in AI & Automation.
  • 6 · AI & Automation reshuffleTools tab per agent, Connectors as a directory, Housekeeping tab, Performance tabs and period. Then Home.
